* Opening a solution no longer freezes the IDE. Projects are evaluated on a background thread and the finished solution is published in one step, with progress in the status bar; the Solution Explorer tree and the Unit Tests pad's source scan are built off the UI thread too. On a 471-project solution (dotnet/aspire) the UI stayed frozen for 31 seconds before and now keeps responding during the load. Opening another solution or closing it meanwhile drops the load in progress, and a previous solution that fails to load at startup still leaves the start page. Contributed by [sharpSteff](https://github.com/sharpSteff) (#39); set `OD_ASYNC_SOLUTION_LOAD=0` for the old behavior.
* MSBuild processes started by the IDE no longer outlive it (#38): reference resolution runs in short-lived processes over chunks of 64 projects (a 4 GB MSBuild server was left behind after opening dotnet/aspire), and no dotnet process the IDE starts uses the MSBuild server.
* WPF Hot Reload applies code changes for projects that use LibreWPF's XAML source generator: editing a `{cs:}` expression or adding an `x:Name` reaches the running app without a restart, with or without the debugger attached (SharpDbg applies the update to the running process). Removing an `x:Name` or changing `x:Class` asks for a restart, and a XAML apply that fails half-way restores the last applied state. Projects that do not enable the generator keep the existing XAML Hot Reload unchanged; nothing requires switching to it.
* The C# language service now compiles projects with their implicit global usings and runs their analyzers and source generators (Regex, LibraryImport, System.Text.Json and so on), so implicit usings and generated members are no longer reported as missing. The SDK's code-quality analyzers are not loaded.
* The XAML editor understands Simpler XAML (implicit namespaces).
* The Help menu now links to OpenDevelop's own GitHub, releases, issues, contributing, third-party notices, sponsor page, and the upstream projects it is built on (AvalonEdit, AvalonDock, ILSpy, LibreWPF, SharpDbg); the obsolete SharpDevelop ReadMe entry is gone.
* Menu items no longer rebuild their children when a nested submenu opens, fixing flicker and stale entries in multi-level menus.
* Android SDK Manager: package listing, checkbox toggles, and the `--install` call now work on Windows by running `sdkmanager` through `cmd.exe`, and an empty package tree no longer crashes the view. The package tree is ordered by level and family, auto-discovers the SDK, and shows a busy indicator while loading.
* A single Device Manager is available on every platform, with localized strings and SDK auto-discovery.
* The About dialog is restyled for dark themes and localized, and the BusyIndicator overlay is themed and shared across the remaining async-loading views.
* ComboBox templates gained an editable text box in both themes, and the implicit ListViewItem style that SharpGridView's container style is based on is now defined.
* All built-in add-ins now carry the IDE's product version, and add-in manifests that named the wrong assembly are corrected, so add-ins load reliably.
* The product version stays at the tag value between releases instead of drifting.
* LibreWPF is upgraded to `0.1.0-preview.69.60.1`, which also publishes the XAML source generator (`LibreWPF.Xaml.SourceGenerator`); an `x:Name` now also sets the element's `Name` and registers it in the root name scope, as BAML does.
* macOS and Windows UI labels that were still in English are now localized.
* The GTK designer no longer lets a preview render that finishes after a newer edit overwrite the newer state, and a save of an outdated version falls back to a recovery snapshot instead of failing.
* The terminal uses LibGhostty.Net 1.0.3.
* The MewUI designer moved to its own repository, [lextudio/MewUI-Designer](https://github.com/lextudio/MewUI-Designer), and is no longer part of this download.
