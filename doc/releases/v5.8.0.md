* Choose what F5 runs from a new drop-down on the Debug toolbar, as in Visual Studio. For an Uno or other multi-target project it lists the profiles in `Properties/launchSettings.json` that match your target frameworks (desktop, iOS, Android), followed by the devices of the chosen platform: iOS simulators or Android devices. A target without a profile offers "Add profile", which writes one into the file and keeps your comments.
* Debug .NET 11 Android apps on a device and iOS apps in the iOS Simulator with F5.
* A new Device Manager lists, creates, starts and stops Android emulators and iOS simulators.
* The Uno designer previews XAML on an iOS Simulator or an Android emulator, with a device frame and rotation.
* Manage NuGet Packages is rebuilt: installs, updates and removals run in the background, and each package shows its deprecation and vulnerability warnings.
* The editor light bulb offers Roslyn quick fixes and refactorings, and can install a package for a missing namespace.
* Code completion filters the list and highlights the matching item as you type again (#25). Each item shows an icon for its kind, and on high-DPI macOS and Linux displays the popup appears right under the word instead of far above it.
* Starting a project applies the selected profile from `Properties/launchSettings.json`, as `dotnet run` does.
* Run Without Debugging (Ctrl+F5) starts the program directly and no longer puts the IDE into the debugging state.
* Clicks in the editor's breakpoint margin hit the right line, including empty lines.
* The designer stays responsive while you edit properties.
* Only WPF XAML opens in the WPF designer; Uno and WinUI documents open in their own Design view.
* The GTK designer adds notebook actions, menus that keep their state, custom widgets that reload, and composite templates.
* Projects can be renamed and deleted in the Project Browser again (#24), and MewUI and GTK files nest under their root file.
* A machine without .NET SDK 10 now says so at startup instead of failing every project (#21).
* Builds use only the SDK chosen in Tools > Options > .NET SDK.
